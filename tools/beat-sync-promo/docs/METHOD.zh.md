# 方法

卡着音乐剪的宣传片要好看，两件事缺一不可：每一次变化都落在歌曲真实的拍点上，同时没有任何变化快到来不及读。本文是模板背后的检查清单，英文版见 [METHOD.md](METHOD.md)。

## 1. 网格要实测，不信标称 BPM

- `prepare_music.py` 先用频谱通量估速度，再在底鼓频段上细化；之后在 drop 附近实测底鼓的起音点，用最小二乘拟合 `t = t0 + k·P`。参考片的歌标称 120 BPM，实测 121.99；如果按 120 排，到第 12 小节剪辑点会偏半拍。
- 残差中位数应在 10 ms 左右以内，即小于 60fps 的一帧。合成测试歌上，拟合残差 0.2～0.4 ms，与真实起音点相差 11～15 ms。
- 授权音乐不要变速（多数免费授权禁止混音），让片子去贴歌。
- 截取时让 drop 落在事先定好的小节线上。模板把它放在第 3 小节第 1 拍，也就是圆从按钮里展开的那一刻。
- 速度会自动折算，让一小节保持在 1.5～3 秒（网格 80～160 BPM）。150 BPM 的歌被测成 300 时会折回 150。歌太慢或太快时片长会变，脚本会明确提示。

## 2. 所有时间都写成 `bt(小节, 拍)`

时间轴里不写死秒数。正因为这样，换一首歌才能让整片自动重新对拍。

- 剪辑落在强拍；UI 交互落在拍、8 分或 16 分音符上，打字一字一个 16 分音符。
- 动作**从拍点起步**：揭示用 outExpo，约 0.1 秒完成 80%，观众感觉是"打在拍上"。大运动反过来：速度峰值放在两拍之间，**停在下一小节的强拍上**（轮播甩镜正好在第 8 小节第 1 拍停到主画面）。
- 一个镜头只讲一件事；大运动可以占两小节（一小节漂移、一小节甩镜）。
- 每个镜头一次缓慢推近（1.00→1.03，inOutSine），不抖、不回弹。

## 3. 停留预算：拍点决定什么时候能变，预算决定能不能变

参考片第一版在 4 秒内换了 7 次画面：先是三次硬切，然后一个换词滚动条。每次变化都在拍上，看起来还是很慌：122 BPM 一拍不到 0.5 秒。`node tools/render.mjs lint` 会用页面里的 `PACING` 清单检查三条规则：

| 规则 | 下限 |
|---|---|
| 两次硬切之间 | 1 小节（约 2 秒） |
| 同一位置替换内容（滚动条换词、卡片翻面） | 2 拍（约 1 秒） |
| 文字的可读时间 | 0.25 秒 + 每个汉字、数字串或英文词 0.1 秒 |

- **叠加不算切换**：同一画面在第 1、2、3 拍依次加入的内容没问题，因为先出现的会一直留着。想按拍打点时，优先"叠加"而不是"替换"。
- **先算预算再出分镜**：把每个镜头的最低停留时间加起来，超过片长就删掉信息量最少的镜头（参考片删了滚动条）。不要靠加快剪辑来解决。
- 检查默认只给建议（退出码 0）；加 `--strict` 才会报错，可用作 CI 把关。

## 4. 声音

- 音效在 `tools/sfx.py` 里现场合成，不用采样，没有授权问题。
- 按**实测峰值**摆放，不按文件起点：whoosh 的峰对甩镜的最高速度，click 对按下的那一刻。
- 每个音效都压在它所在位置的音乐下面：增益上限是比当地音乐低 3 dB，前奏很安静时会自动压低。
- 响度：两遍 loudnorm 到 −14 LUFS，再过一级限幅器。AAC 编码会让真峰值升高约 0.3 dB，所以混音目标定在 −1.9 dBFS。

## 5. 画面

- 页面是时间的纯函数。`renderAt(t, ft)` 里，`t`（子帧时间）驱动运动，`ft`（帧中心时间）决定显示哪个镜头，所以子帧模糊不会跨过硬切产生残影。
- 每帧取 3 个子帧（t ± 1/240 秒），用 `tmix` 混合，得到 60fps 下的真实运动模糊。但大面积的快速边缘会采样不足：展开的圆曾出现灰环，后来按边缘在一个子帧跨度内移动的距离做羽化才解决。甩镜另加随角速度变化的水平 SVG 模糊，挂在非 3D 的外层容器上。
- 匹配剪辑的位置在运行时测量：钩子词 → 文件标签，按钮 → 圆，主卡片 → 手机屏幕。
- 不要给 `preserve-3d` 元素设 `opacity` 或 `filter`，否则会被压平、两面同时可见。淡入淡出和模糊都放在外层容器上。
- 片段是逐帧切换的 JPEG 序列，截图前要 `await img.decode()`。
- 帧与帧互相独立，所以可以开多个页面分段并行渲染（M 系列 Mac 上 4500 个子帧约 1 分钟）。只想重渲一段时，删掉 `build/subframes` 里对应的范围即可。

## 6. 内容规矩

- 对外发布的片子**只用真实素材**。`make_test_clips.sh` 生成的画面只是跑流程用的替身。
- 屏幕上的数字必须可核实，并且讲产品能给用户什么（模板数量、授权配乐、在哪里运行），不要用开发机的历史数据。每个数字都要记下出处。
- 如果"在本机"有例外，要在画面上写明。
- 屏幕文字不带句号。只用一种强调色；浅色背景上把它做成深色文字下面的色块，不要直接当文字颜色。
- 16:9 素材裁成 9:16 时，只取中间 72% 的高度，避免出现被切一半的标题和字幕条；跳过片尾卡和其他品牌的标志。

## 7. 踩过的坑

| 现象 | 原因与修法 |
|---|---|
| 展开的圆出现灰环 | 3 个子帧撑不住大面积快速边缘，改为按位移量解析羽化 |
| 飞行的字、光标或圆看不见 | 场景设了 z-index，浮层没设 |
| 下一镜头的淡入被挡住 | 上一镜头的背景盖住了它，改用独立的底色层 |
| 字标压在标志上 | 标志先移位，字标晚 0.3 秒再揭示 |
| 截出来的音乐是静音 | `-ss` 放在输出端时，`afade` 按歌曲原始时间计时，改用 `atrim,asetpts` 截取 |
| loudnorm 测到 TP > 0 | 混音写成 int16 时已经削波，先整体降低再标准化 |
| zsh 里 `$var:linear` 被截断 | zsh 的历史修饰符，写成 `${var}` |
| Playwright 找不到浏览器 | `render.mjs` 会先试本机 Chrome，否则运行 `npx playwright install chromium` |
